## 로컬에서 보기

별도 빌드나 패키지 설치 없이 정적 파일을 제공합니다.

```sh
python3 -m http.server 4173 --bind 127.0.0.1 --directory dist
```

브라우저에서 http://127.0.0.1:4173 을 엽니다.

## 파일

- `dist/index.html`: 페이지 구조
- `dist/styles.css`: 반응형·인쇄 스타일
- `dist/data-public.js`: 공개 여행 일정·준비 항목·출처
- `dist/app-public.js`: 일정 전환·문구 복사·기기별 체크와 메모
- `dist/assets/`: 사이트 이미지. 이미지 출처는 사이트 데이터에 표시됩니다.

운영시간·예약·통신 요금 조건은 자료 확인일 이후 변경될 수 있습니다. 개인정보나 예약 원문을 저장소에 추가하지 마세요. 체크와 메모는 방문자의 브라우저에 저장됩니다.

## 소스 관리

이 저장소는 공개 사이트의 정제된 소스를 새 이력으로 보관합니다. Sites의 내부 배포 설정과 과거 원본 Git 이력은 포함하지 않습니다. 저장소는 비공개로 유지합니다.

### 사이트 수정 시 GitHub 함께 갱신

로컬 Sites 소스가 커밋되면 관리용 `post-commit` 후크가 `scripts/sync-site.py`를 실행합니다. 공개 `dist/`만 검사해 이 저장소에 복사하고, 변경분을 커밋한 뒤 GitHub `main`으로 push합니다. 사이트를 배포한 뒤에도 명시적으로 동기화·검증해 후크 실행 실패를 확인합니다.

```sh
# 현재 작업 공간에서 실행. 기본 원본은 옆 폴더 shanghai-tech-2026입니다.
python3 scripts/sync-site.py --dry-run
python3 scripts/sync-site.py
python3 scripts/sync-site.py --check
```

`--check`는 개인정보 검사와 원본/미러의 파일 일치를 확인하며, 다르면 종료 코드 1을 반환합니다. `--dry-run`은 차이만 표시하고 전송하지 않습니다. 기본 실행에는 Git, GitHub CLI(`gh`) 로그인, 깨끗한 `main` 작업트리가 필요합니다. GitHub에 다른 커밋이 생기면 먼저 병합해야 하며 강제 push는 하지 않습니다. GitHub push 자체는 공개 사이트를 배포하지 않습니다.

후크 설치는 로컬에서 한 번 실행합니다. 기존 셸 후크 내용은 보존하고 관리 블록을 추가합니다. 사용자 지정 `core.hooksPath` 또는 셸이 아닌 후크는 자동 변경하지 않습니다.

```sh
python3 scripts/sync-site.py --install-hook
```

후크는 이 컴퓨터의 Sites 체크아웃에만 설치됩니다. 다른 컴퓨터에서는 원본 경로와 검사용 목록을 준비하고 다시 설치해야 합니다. 후크가 실패해도 Sites 소스 커밋은 유지되며, 오류를 해결한 뒤 기본 명령을 다시 실행하면 대기 중인 GitHub push도 재시도합니다.

### 공개 소스 검사

- 정적 웹 파일과 이미지·폰트만 허용하며 숨김 파일, 호스팅 설정, 소스맵, 예약 문서, 압축파일은 제외합니다.
- 심볼릭링크, 알려진 비공개 표식, 민감한 예약·여권 필드, 자격증명 패턴, 검토가 필요한 이미지 EXIF를 발견하면 전송을 중단합니다.
- 원본 Git 관리 폴더의 `site-sync-private-markers.sha256`는 로컬 전용 검사 목록입니다. 각 비공개 표식을 `casefold()`한 뒤 `문자길이:SHA256 UTF-8 해시` 형식으로 한 줄씩 보관합니다. 이 목록과 개인정보 원문은 GitHub에 올리지 않습니다.
- 자동 검사는 보조 수단입니다. 새 여행 정보나 이미지를 추가할 때는 공개 가능한 내용과 출처인지 먼저 확인합니다.
